Os motores

Sete motores, cada um com a sua tarefa.

Cada ferramenta de IA costuma carregar o próprio modelo, o próprio servidor, o próprio processo. Aqui vivem sete motores locais que fazem esse trabalho uma única vez por máquina e atendem o Claude Code, o Codex, o Copilot, o Cursor e os seus scripts.

Cada card abre a página do próprio produto. Onde ela ainda não existe, o botão leva à versão atual para baixar.

vozWindows

Vox Engine

Dita, transcreve, traduz e lê em voz alta — com um único motor de voz local compartilhado por todos os apps.

Para quem: quem dita textos, transcreve gravações ou quer ouvir a resposta do agente. Como usa: instala uma vez e os aplicativos pedem voz ao mesmo motor.

VXK

Seu agente escreve o roteiro; o VXK entrega a explicação pronta, em página animada e narrada que abre offline.

Para quem: quem pede ao agente para explicar algo difícil com imagem e voz. Como usa: o agente chama o VXK por MCP e recebe um único arquivo HTML.

MCPqualquer sistema

mcp-gateway

Conecta uma vez em cada servidor MCP e entrega todas as ferramentas por um endereço só, com senha.

Para quem: quem abre várias sessões de agente e não quer um processo por servidor em cada uma. Como usa: cada sessão aponta para o mesmo endereço local.

Para quem: quem quer que o agente “assista” a um vídeo por link ou arquivo. Como usa: o agente pede a leitura por MCP e consulta o resultado depois.

embed-house

Carrega o modelo de embeddings uma só vez e serve vetores a todos os consumidores, em vez de cada sessão carregar cerca de 147 MB.

Para quem: plugins e agentes que fazem busca por significado. Como usa: o app consulta um endereço local e recebe os vetores.

neural-link

Recebe cada evento de hook do agente, pontua os handlers registrados e devolve uma única decisão composta.

Para quem: quem roda agentes com hooks no Copilot CLI, no VS Code ou no Claude Code. Como usa: o agente o chama a cada evento; ele não fica rodando em segundo plano.

skill-engine

Busca as skills de repositórios git em quarentena, confere com regras fixas e só ativa o que sai limpo, nas pastas que cada agente lê.

Para quem: quem usa skills de terceiros no Claude Code, no Codex, no Copilot ou no OpenCode e quer conferir antes de ativar. Como usa: o comando skill-engine registra o repositório, verifica e ativa; ele não fica rodando em segundo plano.

Como se conectam

Cada motor funciona sozinho. Juntos, se encaixam.

Nenhum motor exige os outros, exceto onde a tabela diz. O mcp-gateway reúne os servidores MCP; o VXK usa o Vox para narrar; o embed-house e o neural-link atendem o agente por conta própria.

Como usar

Instalar uma vez. Usar em qualquer lugar.

Escolha o motor

Cada motor tem a sua página ou a versão atual para baixar. Os que precisam de instalador trazem o próprio e se atualizam sozinhos.

Instale pelo kit

Num clone do repositório, um comando confere a máquina e instala ou atualiza o que faltar.

node kit/doctor.mjs --fix --engine vxk

Use nos seus apps

Os aplicativos e agentes encontram o motor que já está instalado e passam a compartilhá-lo. Atualizou? Todos recebem a nova versão ao mesmo tempo.
